# Phase 18.1 Plan 05: PII named-detector registry Summary

Replaced the empty PII implementation (zero built-in detectors) with an extensible named-detector registry — ssn (dashed+undashed), credit_card (Luhn), email, phone (US+E.164), iban (mod-97), ip (v4), jwt, api_key (AKIA/sk-/ghp_/xox) — selectable via `guardrails.pii.detectors:[...]`, defaulting to the prior 3-pattern behavior when omitted.

## What Changed

- `pii.ts`: added `PII_DETECTORS` registry, `DETECTOR_NAMES`, `luhnValid`, `ibanMod97Valid`, and `PiiDetector`/`DetectorName` types. `createPiiAssertion` now runs the selected named detectors (with per-detector checksum validation) when `detectors` is set, else the legacy `denyPatterns` path. The `hasNestedQuantifiers` ReDoS guard is preserved and still applied to user `denyPatterns` and `customPatterns`. `safeRegexExec` also guards against zero-width matches.
- `schema.ts`: added `detectors` (Zod enum array from `DETECTOR_NAMES`) to the strict `PIIGuardrailSchema`; default denyPatterns untouched.
- `registry.ts`: threads `detectors` into `createPiiAssertion`.
- `README.md`: PII feature line + example now list only detectors that actually fire and document the `detectors` config + back-compat default.

## Detector Acceptance Table

| Detector | Positive (fires) | Negative control (does not fire) |
|---|---|---|
| ssn | `123-45-6789`, `123456789` | `the year was 2024 ...` |
| credit_card | `4111 1111 1111 1111` (Luhn-valid) | `4111 1111 1111 1112` (Luhn-invalid) |
| email | `jane.doe@example.com` | plain text |
| phone | `(415) 555-2671`, `+14155552671` | `press 5 to continue` |
| iban | `GB82WEST12345698765432` (mod-97-valid) | `GB82WEST12345698765433` (mod-97-invalid) |
| ip | `192.168.1.42` | `999.999.999.999` |
| jwt | 3-segment base64url token | `header.payload` (2 segments) |
| api_key | `AKIA...`, `sk-...`, `ghp_...`, `xoxb-...` | random text |

Luhn rejects the bad card; mod-97 rejects the bad IBAN (unit-tested both accept and reject directions).
