# Phase 18.1 Plan 02: Inject argsSchema Validator Into AssertionContext Summary

Wired an AJV-backed `validateJsonSchema` into every AssertionContext the runner builds (final/test-level, per-turn, command), so tool-call `argsSchema` assertions now validate real arguments instead of failing with "argsSchema provided but no JSON Schema validator was injected". A single shared `createJsonSchemaValidator()` factory is the one AJV config, consumed by both the output-schema assertion and the runner.

## What Changed

- **`assertions/schema.ts`**: Extracted `createJsonSchemaValidator()` (and `JsonSchemaValidationResult` type) as the single AJV configuration (`new Ajv({ allErrors: true, strict: false })` + `ajv-formats` + per-schema compiled-validator cache). `createSchemaAssertion` now consumes the shared validator; AJV is no longer instantiated inline in two code paths. Compile errors are flagged (`compileError: true`) so the existing "Schema compilation failed" message is preserved.
- **`assertions/index.ts`**: Barrel-exports `createJsonSchemaValidator` + `JsonSchemaValidationResult`.
- **`engine/runner.ts`**: One module-level `validateJsonSchema = createJsonSchemaValidator()` injected into all three AssertionContext construction sites (lines 391 final, 402 per-turn, 628 command).
- **Tests**: New `json-schema-validator.test.ts` (5 tests: pass/fail, `additionalProperties:false` enforcement, formats enabled, compile-error reporting). New runner regression block "argsSchema validator injection (ROADMAP #2)" (4 tests): FAILS on leaked/extra args under `additionalProperties:false`, PASSES on matching args, presence across main+per-turn contexts, and command-test context — each asserting the "no validator injected" message is absent.

## Deviations from Plan

**1. [Rule 3 - Blocking] Static AJV imports + synchronous validator**
- **Found during:** Task 1
- **Issue:** The pre-existing schema.ts used dynamic `import("ajv")` returning an async validator. The AssertionContext.validateJsonSchema contract is synchronous (`(schema, data) => { valid } | { valid:false; errors }`), so an async helper could not be injected directly.
- **Fix:** Switched to static `import Ajv from "ajv"` / `import addFormats from "ajv-formats"` (already direct deps of core) and made the factory synchronous. Kept identical AJV options + formats + cache.
- **Files modified:** packages/core/src/assertions/schema.ts
- **Commit:** this plan's commit

**2. [Rule 1 - Behavior preservation] Distinguish compile errors**
- **Found during:** Task 1 (schema.test.ts expected "compilation failed")
- **Issue:** Collapsing compile + validation errors into one array changed the existing failure message.
- **Fix:** Added `compileError?: boolean` to the result; schema.ts emits "Schema compilation failed" vs "Schema validation failed" accordingly. Existing test passes unchanged.
