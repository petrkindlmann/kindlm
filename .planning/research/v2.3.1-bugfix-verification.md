# v2.3.1 Bugfix — runtime verification against local source

**Date:** 2026-05-30
**Method:** Built `@kindlm/core` from local source, registered a fake fault-injecting
provider, drove the real `parseConfig` + `createRunner` + assertion pipeline via
`/tmp/kindlm-repro/repro.mjs`. Every verdict below is from an executed reproduction,
not from reading code.

Source plan: `~/Downloads/kindlm-fix-plan.md` (tested against npm `@kindlm/cli@2.3.0`).
Local source had drifted from the npm build, so each item was re-verified.

## Confirmed verdicts

| # | Item | Plan said | Local-source runtime verdict |
|---|------|-----------|------------------------------|
| 1 | Typo'd `expect` keys pass green | bug | **CONFIRMED.** `parseConfig` accepts `tooCalls`/`guardrailz`/`completely_made_up_key`; test runs with **0 assertions** and status `passed`. `.strict()` count in schema.ts = 0. |
| 2 | `argsSchema` validator never injected | bug | **CONFIRMED.** Schema *content* resolves into `argsSchemaResolved` and reaches the assertion, but `runner.ts buildAssertionContext` (line ~388) never sets `context.validateJsonSchema`, so `tool-calls.ts:76` always returns "argsSchema provided but no JSON Schema validator was injected". Root cause is the **runner context**, not CLI path-gathering. Fails closed (good). |
| 3 | Ordering not enforced from YAML | bug | **CONFIRMED for plain list.** `registry.ts:28` only builds `createToolOrderAssertion` when some `tc.order !== undefined`. A plain `toolCalls` list (no `order:`) gets presence-only checks → refund-before-lookup **passes**. The numeric `order:` field DOES enforce sequence; there is no `ordered: true` opt-in. |
| 4 | Reports stamp `version: 0.0.0` | bug | **CONFIRMED with precise root cause.** `select-reporter.ts` passes `process.env.npm_package_version` to `createJsonReporter`. For an installed binary (not `npm run`), that env var is **undefined** → `createJsonReporter(undefined)` → `json.ts:11` stamps `0.0.0`. Compliance metadata is OK (test.ts:269 uses `KINDLM_VERSION`). **Fix:** replace the env-var read in `select-reporter.ts` with the bundler-injected `KINDLM_VERSION` constant. |
| 5 | PII covers 3 of ~14 advertised | bug | **CONFIRMED.** `pii.ts` has **zero built-in detectors** — it only compiles user `denyPatterns` (3 schema defaults: dashed-SSN, CC, email) + `customPatterns`. Undashed SSN, IBAN, IP, JWT, AWS key, intl phone all MISSED. (CC/email default patterns exist but are format-fragile.) |
| 6 | `--no-cache` still serves reads | **ALREADY FIXED in local source.** `init-adapters.ts:130` skips wrapping the caching adapter entirely when `noCache` — with no caching adapter there is no read path. The npm-2.3.0 symptom is gone. Action: regression test only (assert two `--no-cache` runs against a counter provider differ). |
| 7 | `--runs N` discards flakiness | PARTIAL | `aggregator.ts` already computes `passRate`, `passedRuns`(via filter), `runCount`. Repro: repeat=10 @ 50% → `aggregated.passRate = 0.5`. But `TestRunResult` collapses to `status: "failed"` — **no `flaky` status, passRate not surfaced** to reporters. This is exactly Phase 19's job (pass^k, variance, repeat=3). |

## Routing decision

User chose: **dedicated bugfix phase, verify-first.**

- Items **1, 4, 5, 6** are pure regressions with no roadmap home → new bugfix phase.
- Item **2** is a runner-context wiring fix (inject `validateJsonSchema` into
  `buildAssertionContext`, reusing the AJV instance pattern from `schema.ts`).
- Item **3** → add opt-in `ordered` flag (or `toolCallOrder`) without breaking the
  existing numeric `order:` path.
- Item **7** → fold into existing **Phase 19** (Reliability & Statistical Foundations);
  do not duplicate.
